0:40 Scene 2 — Architecture Overview 35 sec
Show on screen

Switch to a slide or diagram showing Aegis's architecture: two pipelines (SBOM/SCA on the left, News Ingestion on the right) converging into the Match Engine in the center, with Slack notifications and a Validator stage below. Below everything, the Ask Aegis RAG chatbot.

Say

Aegis has two independent data pipelines that converge at a central match engine.

Say

Side A is the SBOM/SCA pipeline. It scans every repository in your organization using Syft, Trivy, and Grype — we call them Cartograph, Auditor, and Sentinel — to build a complete inventory of every dependency, its version, its license, and known vulnerabilities. This runs nightly on a cron.

Say

Side B is the news ingestion agent. It polls 22 security sources — RSS feeds from Socket.dev, Snyk, CISA, The Hacker News, plus the NVD and CVE Crowd APIs — every 30 minutes. Articles pass through a keyword relevance filter, a vendor blocklist, a three-phase deduplication system, and then an LLM enrichment stage that classifies each article and extracts structured package data.

Say

When a supply chain vulnerability is detected, the match engine cross-references it against the SBOM inventory, fires a Slack alert, and spawns ECS Fargate validators for reachability analysis. And Ask Aegis, our RAG chatbot, lets anyone on the team query the entire knowledge base in natural language. Let's walk through each stage.

$ aegis demo sbom --fast
Say (while output scrolls)

Here's the SBOM pipeline running against a sample repository called checkout-service. Six stages:

Say

First, Cartograph — our Syft wrapper — discovers 142 components. Then Auditor — wrapping Trivy — independently finds 138 components with license metadata that Cartograph doesn't capture. Stage three fuses these two SBOMs by PURL union into a merged inventory of 146 unique components.

Point at the terminal output as each stage completes
Say

Now Sentinel — our Grype wrapper — matches this merged SBOM against vulnerability databases: NVD, GitHub Advisories, and distro feeds. It finds 4 vulnerabilities, including a critical one in axios version 1.14.1 — a backdoored release.

Say

The Licenser then enriches missing license data through a three-tier waterfall: pattern rules, the deps.dev API, and GitHub API fallback — reaching 95% coverage. Finally, everything is uploaded to S3 and Postgres. The SBOM pipeline takes about 4 seconds per repo — we run it nightly across the entire organization.

2:05 Scene 4 — News Ingestion Agent Demo 55 sec
$ aegis demo news --fast
Say

Now the news side. The agent polls 22 sources organized in four tiers — from supply-chain first responders like Socket.dev and Snyk, through deep-analysis outlets like Unit42 and Wiz, government feeds from CISA and NVD, down to general security press. Plus two API sources: the NVD critical-CVE endpoint and CVE Crowd's trending feed.

Say

This cycle fetched 8 new articles. Watch the relevance filter — it's keyword-based across categories like supply chain, ecosystems, severity, and breach indicators. It also runs a vendor blocklist: Citrix and FortiGate articles get blocked because we don't run that infrastructure, but it has override logic — if a blocklisted vendor's article also mentions npm or supply chain, it gets rescued.

Point at the PASS/BLOCK lines in the output
Say

Next is three-phase deduplication: exact URL match, fuzzy title comparison with Jaccard similarity, and then LLM-powered semantic dedup. Notice it catches that the two axios articles from different sources are the same incident — Jaccard score 0.73, above our 0.70 threshold.

Say

Finally, the LLM enrichment stage. Each article is sent to an LLM with a carefully engineered prompt that classifies it into one of three buckets: supply_chain_vuln for dependency-level threats, threat_intel for infrastructure vulnerabilities like Grafana, or general_info. For supply chain vulns, it extracts the real installable package name, ecosystem, and version constraints. The enrichment prompt has strict rules — vulnerability nicknames like "Log4Shell" get translated to actual package names, and vague version strings get rejected.

3:00 Scene 5 — Match Engine + Validator 45 sec
$ aegis demo match --fast
Say

This is the bridge — where threat intelligence meets your actual inventory. The match engine takes the structured package data from the news pipeline and queries the SBOM database.

Say

For axios, it runs a four-step lookup: first an exact name match scoped to the npm ecosystem, then without ecosystem, then a fuzzy match using rapidfuzz for typos and naming divergence, and finally a "not found" safe designation. It finds 40 repos using axios. Now it compares each repo's installed version against the vulnerable range — 1.14.1 and 0.30.4. Three repos are flagged vulnerable. Thirty-seven are safe.

Point at the VULNERABLE vs safe markers scrolling in the output
Say

For the typosquat package "reqeusts" — misspelling of requests — it's not found in any SBOM. Automatically marked safe. No alert, no noise.

Say

For the three vulnerable repos, Aegis spawns ECS Fargate tasks that perform reachability analysis — does the vulnerable code path actually get exercised? Two repos are confirmed reachable, meaning the backdoored axios code is actively called. One repo imported it but never calls it — lower priority. All of this posts automatically to the Slack thread.

Ask Aegis is a RAG-powered security chatbot. It indexes your SBOM inventory, news articles, match results, and remediation guides into a vector store. When someone asks "Are we affected by the axios compromise?", it retrieves the four most relevant sources — the news article, the match result, a remediation playbook, and a related incident — and generates a grounded, cited answer.

Say

It tells you: yes, three repos are affected, here they are by name and version, two have confirmed reachable code paths, and here are your four remediation steps in priority order. It can also pull in historical context — similar past incidents like the event-stream compromise of 2018 or the ua-parser-js hijack — to inform the response. Every answer cites its sources and says "I don't know" when the knowledge base doesn't have the answer.
